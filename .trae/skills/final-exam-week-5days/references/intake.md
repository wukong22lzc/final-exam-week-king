# 输入采集与资料入库

## 1. 给用户的采集卡（可直接复制）

```markdown
【课程档案】
学校 / 课程名 / 课程代码：
课程类型：水课 / 专业课 / 特殊课程（实验·艺术·体育·语言·思政）
考核方式与占比：论文 __% / 考试 __% / pre __% / 作品 __%
剩余天数：5 天 / 3 天 / 24 小时
硬性要求：字数__ 页数__ 参考文献__篇 查重率≤__% 是否有格式模板__

【1 重点资料】
上传老师课件、自己整理的重点（PPT / PDF / Word / JPG 均可）
请标出：老师反复强调的、明确说"必考"的内容

【2 课程书籍】
书名 + 作者（有版次/出版社/ISBN 更好）：

【3 其他资料】
学校：
课程名 + 课程代码：
老师姓名：
自己 / 小组姓名：
学号：（仅用于检索，产出中会脱敏）

【4 我的想法】
论文 idea：
作品 / 脚本 idea：
pre PPT 风格偏好：
复习资料里我最缺的部分：
```

## 2. 文件读取策略

| 文件类型 | 做法 |
|---|---|
| PPT / PPTX | 逐页提取标题与正文要点，先看目录页与章节小结；图表单独记录 |
| PDF（文本层） | 按章节抽取；长文档先读目录，再定位重点章 |
| PDF（扫描件）/ JPG | 先 OCR；识别率低时请用户补文字版，不猜测内容 |
| Word | 提取标题层级，保留老师标注的"重点/考点/必考" |
| 压缩包 / 多文件 | 先按文件名归类，同一章节归为一条记录，避免重复计入 |

单份资料超过 50 页时：读目录 + 每章首尾页 + 老师标注页，中间抽样；在台账中注明"抽样读取"。

## 3. 资料台账（内部使用，最终写入资料清单）

| # | 资料名 | 类型 | 来源 | 覆盖章节 | 核心考点 | 可信度 | 备注 |
|---|---|---|---|---|---|---|---|
| 1 | 第3-5章 课件 | 老师PPT | 用户上传 | 第3-5章 | 三个模型 + 两个计算题 | 高 | 与教材口径一致 |

要求：

- 每份资料至少填满"覆盖章节 / 核心考点"两列，否则视为未读完。
- 重复内容合并为一条，注明"与 #2 重复 70%"。
- 冲突内容单列，写清"按谁处理、为什么"。

## 4. 缺口追问话术

只问三类问题，一次问完：

1. **时间与权重**："还剩几天？论文/考试/pre 各占多少分？"
2. **交付选择**："这次要哪几样：复习资料 PDF / pre PPT / 论文内容 / Word 其他？（可多选）"
3. **硬性门槛**："字数或页数有要求吗？参考文献要几篇？查重率卡多少？有没有老师给的模板？"

能推断就先推断：

- 没说字数 → 论文按 4000 字，标注"可按老师要求调整"。
- 没说 PPT 页数 → pre 10–15 页。
- 没说课程类型 → 从考核方式反推（交论文多为水课，闭卷多为专业课）。
- 没给书籍 → 用课件目录反推教材章节结构，并提示用户补书名。

**不要问**：用户的专业背景、学习习惯、职业规划等与交付无关的信息。

## 5. 缺失与异常处理

| 情况 | 处理 |
|---|---|
| 完全没上传资料 | 先用课程名与教材做公开检索，产出"课程画像 + 待补清单"，请用户补课件后再精修 |
| 只有图片且模糊 | 请用户补清晰版或文字版；先用能识别的部分做骨架 |
| 老师课件与教材冲突 | 以老师课件与考核要求为准，清单中标注冲突 |
| 用户提供的学号/姓名 | 仅用于检索定位，写入文档前一律脱敏 |
| 课程代码查不到 | 不编造，写"未检索到该课程代码的公开信息" |

## 6. 课程画像输出（给用户看的第一份东西）

不超过一屏：

- 这门课考什么：考核方式、分值分布、老师偏好
- 资料够不够：已有 vs 缺口
- 打法：先做什么、砍掉什么、5 天怎么排
- 需要用户确认的 3 件事
